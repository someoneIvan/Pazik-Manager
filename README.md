# Pazik Manager

Настольное приложение для транспортных фотографов: каталогизация, систематизация
и поиск фотографий в больших личных архивах.

Pazik Manager **не** транспортная база данных, не социальная сеть и не
фотохостинг — это инструмент управления собственным архивом пользователя.

## Возможности (MVP)

- Добавление папок в библиотеку и рекурсивное сканирование вложенных каталогов.
- Определение формата, размеров и метаданных снимка (EXIF + ExifTool).
- Определение даты съёмки по EXIF `DateTimeOriginal`.
- Генерация и кэширование миниатюр, в том числе из RAW (встроенное превью).
- Единый интерфейс: тёмная тема, полноэкранный режим, галерея с масштабом,
  панель сведений о снимке, фильтры и поиск.
- Полноэкранный просмотр фотографии с зумом (колесо мыши) и навигацией.
- Система тегов с категориями (транспорт, модель, бортовой номер, парк, город,
  поездка, дата, пользовательские теги) — можно создавать свои категории и теги.
- Одна фотография — несколько тегов; один тег — много фотографий.
- Поиск и фильтрация: по имени, тегам, камере, объективу, дате, наличию файла.
- Повторное сканирование не создаёт дубликатов; отсутствующие файлы помечаются,
  но не удаляются. Перемещённые файлы распознаются и «перепривязываются».
- Если папка переехала или сменилась буква диска: ПКМ по библиотеке →
  «Указать новую папку…» — пути обновятся, теги сохранятся.
- Пересекающиеся библиотеки (папка внутри другой) не добавляются, чтобы не
  индексировать одни и те же файлы дважды.
- Оригиналы фотографий **никогда** не изменяются, не перемещаются и не
  переименовываются при импорте.

## Технологии

- **Python 3.12+**
- **PyQt6** (Qt Widgets) — интерфейс, стилизация через QSS.
- **ExifTool** — чтение метаданных и превью, в том числе из RAW (внешняя
  программа, см. ниже).
- **Pillow** — работа с изображениями и создание миниатюр.
- **pathlib**, **sqlite3** (стандартная библиотека) — файловая система и хранение.

## Установка

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### ExifTool (для RAW-файлов)

JPEG/PNG/TIFF полностью работают без ExifTool. Для RAW (CR2/CR3, NEF, ARW, DNG,
RAF, ORF, RW2 и др.) нужен ExifTool — он читает метаданные и извлекает встроенное
превью камеры.

- **Windows**: скачайте `exiftool-13.xx_64.zip` с https://exiftool.org,
  распакуйте и положите `exiftool.exe` в `resources/tools/` (рядом с проектом)
  либо в любую папку из `PATH`.
- **macOS**: `brew install exiftool`
- **Linux**: `sudo apt install libimage-exiftool-perl` (или пакет вашего дистрибутива)

Приложение само находит ExifTool в `resources/tools/`, `PATH` и типовых местах
установки. Статус можно посмотреть в меню **Справка → ExifTool**.

## Запуск

```bash
python main.py            # полноэкранный режим (по умолчанию)
python main.py --windowed # обычное окно (удобно для разработки)
```

Приложение запускается в полноэкранном режиме. **F11** переключает полноэкранный
режим, **Esc** возвращает в окно.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `F11` | Полноэкранный режим |
| `Esc` | Выйти из полноэкранного режима / закрыть просмотр |
| `Ctrl+F` | Перейти к поиску |
| `F5` | Обновить (пересканировать) библиотеки |
| `Ctrl+O` | Добавить папку |
| `Ctrl+T` | Менеджер тегов |
| `Ctrl+Shift+T` | Назначить теги выбранному фото |
| `Enter` | Открыть выбранное фото |
| `←` / `→` | Предыдущее / следующее фото в просмотре |
| `0` / `1` | Вписать в окно / масштаб 1:1 |
| `+` / `-` | Зум в просмотре |

## Тесты

```bash
python -m pytest -q
```

Тесты используют поддельный ExifTool, поэтому RAW-логика проверяется и без
установленного ExifTool.

```

core/                   — бизнес-логика без зависимостей от Qt
    catalog.py          — высокоуровневый API каталога (библиотеки, фото, теги, поиск)
    database.py         — SQLite: подключение, схема, миграции
    scanner.py          — рекурсивное сканирование (инкрементальное, с отменой)
    metadata.py         — извлечение метаданных (ExifTool + Pillow)
    exiftool.py         — обёртка над ExifTool и извлечение RAW-превью
    thumbnail.py        — генерация и атомарный кэш миниатюр
    identification.py   — идентификация файлов (частичный хеш, размер, mtime)
    models.py           — дата-классы и константы форматов
    paths.py            — расположение данных, кэша и логов
ui/                     — слой представления (PyQt6)
    main_window.py      — главное окно, меню, горячие клавиши, очередь сканов
    sidebar.py          — библиотеки и теги, контекстное меню
    gallery.py          — галерея миниатюр (масштаб, кэш иконок, контекстное меню)
    photo_info.py       — сведения о фото и управление тегами
    tag_editor.py       — диалоги назначения/управления тегами
    filters.py          — панель фильтров
    viewer.py           — полноэкранный просмотр с зумом
    workers.py          — фоновая нить сканирования (с отменой)
    theme.py            — загрузка QSS и иконок
resources/
    styles/dark.qss     — тёмная тема
tests/                  — pytest (ядро + offscreen-тесты интерфейса)
```

### Хранение данных

Каталог — один файл SQLite в каталоге данных пользователя
(`%APPDATA%\PazikManager` на Windows, `~/.local/share/PazikManager` на Linux).
Путь можно переопределить переменной `PAZIK_DATA_DIR`.

- Миниатюры: `<данные>/cache/thumbnails/`
- Логи: `<данные>/logs/pazik.log`

Схема спроектирована так, чтобы в будущем можно было добавить полноценные
сущности (карточки транспортных средств, моделей, парков), не переписывая
систему каталогизации: теги универсальны и делятся на категории.

### Идентификация файлов

- Первичный ключ — `(library_id, path)`.
- `instance_id` — XMP/EXIF `InstanceID` / `ImageUniqueID`, если присутствует.
- `content_hash` — быстрый **частичный** хеш (начало + конец + размер),
  вычисляется один раз при импорте, а не при каждом сканировании.

При повторном сканировании неизменившиеся файлы (совпадают размер и mtime)
пропускаются целиком: метаданные и RAW-превью повторно не читаются. Перемещённые
файлы ищутся среди «отсутствующих» по InstanceID, хешу или имени+размеру, поэтому
теги сохраняются.

### RAW-файлы

- Оригиналы только читаются; ничего не записывается в RAW и рядом с ним.
- Метаданные и встроенное превью извлекаются через ExifTool.
- Используются теги `PreviewImage`, `JpgFromRaw`, `OtherImage`,
  `ThumbnailImage`, `PhotoshopThumbnail` (первое валидное изображение).
- Если превью нет — миниатюра не создаётся, но файл остаётся в каталоге.
- Если ExifTool не установлен, RAW индексируются без метаданных; после установки
  ExifTool выполните **Файл → Пересоздать миниатюры** (или пересканируйте).

### Переносимость и XMP (на будущее)

Сейчас теги хранятся локально. Архитектура готова к последующей синхронизации
пользовательских тегов с XMP (для RAW — через XMP Sidecar-файлы), без изменения
оригиналов.
